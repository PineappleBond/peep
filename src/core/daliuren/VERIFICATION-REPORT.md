# 大六壬 TypeScript 实现 - PHP 对比验证报告

## 项目概述

本项目完成了大六壬算法从 PHP（meixiaoqiu/liuren）到 TypeScript 的完整移植，并通过 5 轮系统性对比验证，确保算法正确性。

## 5 轮验证过程

### 第 1 轮：基础对比（10 个案例）
- **目标**：建立 PHP vs TS 对比测试框架
- **发现**：早子时处理错误
  - PHP 将 23:00-00:00 视为次日（早子时）
  - TS 原版视为当日（晚子时）
- **修复**：`hour >= 23` 时自动进日
- **结果**：10/10 通过 ✅

### 第 2 轮：深度边界测试（29 个案例）
- **覆盖**：子时边界、节气边界、特殊日柱、十二时辰全覆盖
- **结果**：29/29 通过 ✅
- **结论**：边界情况处理正确

### 第 3 轮：九宗门专项测试（28 个案例）
- **覆盖**：所有九宗门取法（元首/重审/比用/涉害/遥克/昴星/别责/八专/伏吟/反吟）
- **结果**：28/28 通过 ✅
- **结论**：核心算法（三传计算）完全正确

### 第 4 轮：辅助计算专项测试（26 个案例）
- **发现 1**：十二天将计算公式错误
  - 原版使用 `heavenBoard[ground]` 计算
  - 应使用地盘位 `ground` 直接计算
- **发现 2**：昼夜贵人判断精度不足
  - 原版使用简化天文公式（误差约 ±30 分钟）
  - 在日出前后几十秒的边界案例出错
- **修复**：
  1. 修正天将计算公式
  2. 实现完整 NOAA 天文算法（约 200 行）
- **结果**：26/26 通过 ✅

### 第 5 轮：全面综合测试（50 个案例）
- **覆盖**：固定案例 + 随机案例
- **结果**：50/50 通过 ✅
- **结论**：所有模块协同工作正常

## 修复的 Bug 汇总

### Bug 1：早子时处理（第 1 轮）
- **问题**：23:00-00:00 应属次日，TS 原版视为当日
- **影响**：四柱计算错误（日柱差一天）
- **修复**：`if (hour >= 23) { 日柱 +1 }`
- **文件**：`src/core/daliuren/calculator.ts`

### Bug 2：十二天将计算公式（第 4 轮）
- **问题**：使用天盘值而非地盘位计算天将
- **影响**：十二天将排列错误
- **修复**：改用 PHP 公式 `tianpan[0] - guiren + i`
- **文件**：`src/core/daliuren/tianjiang.ts`

### Bug 3：昼夜判断精度（第 4 轮）
- **问题**：简化天文公式误差大，边界案例出错
- **影响**：贵人顺逆判断错误
- **修复**：实现完整 NOAA 算法（儒略日、时差方程、太阳赤纬等）
- **文件**：`src/core/daliuren/tianjiang.ts`
