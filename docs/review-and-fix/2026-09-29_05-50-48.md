## 二、核心重构：rtcAgent.ts 按业务域拆分

### 2.1 问题

`src/core/rtcAgent.ts` 是一个 2643 行的单体文件，包含所有 6 个业务域的 Function 定义、Zod Schema、Agent 创建逻辑和主题同步。这是上一轮审查中明确列出的技术债务。

### 2.2 解决方案

将单体文件拆分为 7 个模块：

| 文件                                     | 行数 | 职责                                                    |
| ---------------------------------------- | ---- | ------------------------------------------------------- |
| `src/core/rtcAgent.ts`                   | 349  | 编排器：聚合 Function Groups、创建 Agent、主题/语言同步 |
| `src/core/rtcAgent/shared.ts`            | 56   | 共享工具：peepApi()、mergeBirthInput、CONFIRM_FIELD     |
| `src/core/rtcAgent/personFunctions.ts`   | 244  | 人物库 Function（6 个）                                 |
| `src/core/rtcAgent/ziweiFunctions.ts`    | 339  | 紫微斗数 Function（3 个）+ 盘面 Schema                  |
| `src/core/rtcAgent/daliurenFunctions.ts` | 442  | 大六壬 Function（7 个）+ 课式 Schema                    |
| `src/core/rtcAgent/liuyaoFunctions.ts`   | 419  | 六爻 Function（7 个）+ 卦象 Schema                      |
| `src/core/rtcAgent/wikiFunctions.ts`     | 321  | Wiki Function（7 个）                                   |
| `src/core/rtcAgent/lunarFunctions.ts`    | 353  | 时间/日历 Function（9 个）                              |

### 2.3 设计要点

- **单一职责**：每个文件只包含一个业务域的 Function 定义和 Schema
- **最小导入面**：rtcAgent.ts 不再直接导入 `z`/`withMeta`，仅从子模块导入 Function 对象
- **向后兼容**：`mergeBirthInput` 从 rtcAgent.ts 重新导出，外部消费者无需改动
- **Schema 复用**：`_daliurenComputed`、`_liuyaoComputed` 等共享 Schema 提取为模块内部常量，消除重复定义
- **零行为变更**：所有 Function 的 name/description/zodSchema/handler/returns 完全保持原样

### 2.4 效果

- rtcAgent.ts 从 **2643 行** 缩减到 **349 行**（-87%）
- 每个业务域文件独立可维护，修改某个域的 Function 不需要在 2600+ 行中导航
- 新增业务域只需新建一个文件并在 rtcAgent.ts 中添加一行 import

## 三、Bug 修复

### 3.1 rtcAgent.test.ts / integration.test.ts：mock 缺少 `.default()` 和 `.union()`

**症状**：两个测试文件加载时崩溃（0 个测试被执行），报 `TypeError: z.boolean(...).optional(...).default is not a function` 和 `TypeError: z.union is not a function`。

**根因**：上一轮新增 `WikiReplaceContent` 和 `WikiInsertContent` Function 时，其 zodSchema 使用了 `.default()` 和 `z.union()` 链式方法，但测试文件中的 `@rtc-agent/component` mock 没有模拟这些 API。

**修复**：在两个测试文件的 `createMockSchema` 中补齐 `default` 和 `union` 方法。

**文件**：

- `src/core/rtcAgent.test.ts`
- `src/core/integration.test.ts`

### 3.2 liuyao.performance.test.ts：1000 条分页遍历超时

**症状**：在完整测试套件中，`1000 条记录的分页遍历` 测试因并行执行 slowdown 超过 5000ms 默认超时而失败。单独运行通过。

**修复**：为该测试单独设置 15000ms 超时。

**文件**：

- `src/core/debugApi/liuyao.performance.test.ts`

### 3.3 预存 TS 类型错误清理（47 个）

**症状**：13 个测试文件中共 47 个 TypeScript 编译错误，不影响运行时但影响 `tsc --noEmit` 输出。

**主要错误模式**：

- `calendar: "公历"` 应为 `"solar" as const`（Person 类型用 `"solar"|"lunar"` 而非中文字符串）
- `LiuyaoListResult` mock 缺少 `page`/`pageSize` 字段
- `LiuyaoHbarState` mock 缺少 `visible` 字段
- Person mock 对象缺少 BirthInput 必需字段

**修复**：逐个修正测试文件中的类型不匹配，使 `tsc --noEmit` 零错误。
