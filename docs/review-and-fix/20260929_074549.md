## 1. 问题发现

通过全面的代码审查，发现以下模式化重复（Code Smell）：

### 1.1 BatchView 循环收集模式——三处完全相同

大六壬/六爻/Wiki 三个模块的 `BatchView` handler 结构完全一致：

```typescript
// 重复出现 3 次（daliurenFunctions.ts / liuyaoFunctions.ts / wikiFunctions.ts）
handler: async (args: Record<string, unknown>) => {
  const parsedArgs = X.zodSchema.parse(args);
  const results = [];
  for (const id of parsedArgs.ids) {
    const record = await peepApi().SomeView({ personId: parsedArgs.personId, id });
    results.push(record);
  }
  return { records/docs: results, count: results.length };
},
```

### 1.2 UpdateTags/UpdateNote 模式——四处相同

大六壬和六爻各 2 个，加上 Wiki 的 ReplaceContent/InsertContent，共 6 处重复：

```typescript
handler: async (args: Record<string, unknown>) => {
  const params = X.zodSchema.parse(args) as { /* 内联类型 */ };
  return peepApi().SomeApi(params);
},
```

### 1.3 personId 字段定义——20+ 处重复

几乎所有 Function 的 zodSchema 都包含相同的 `personId` 可选字段定义，包括完全一致的 `withMeta(z.number().int().positive(), { example: 1 }).optional().describe("命主 ID（可选）；省略则使用默认人物")` 文本。分散在 5 个文件 20+ 处，任何文案修改都要改 20 处。

### 1.4 未使用导入

`personFunctions.ts` 导入了 `extractConfirmed` 但从未使用（dead import）。

## 2. 修复方案

### 2.1 shared.ts 新增共享工具

| 工具                          | 用途                              | 消除重复数 |
| ----------------------------- | --------------------------------- | ---------- |
| `PERSON_ID_OPTIONAL`          | 统一可选命主 ID schema            | 20+ 处     |
| `PERSON_ID_REQUIRED`          | 统一必选命主 ID schema            | 预留       |
| `createPassthroughHandler`    | parse→call 工厂（用于 List/View） | 通用       |
| `createBatchViewHandler`      | 批量查看工厂（循环收集模式）      | 3 处       |
| `createMetadataUpdateHandler` | 元数据更新工厂（parse→call 通用） | 6+ 处      |

### 2.2 各 Function 文件重构

**daliurenFunctions.ts**：

- 6 处 `personId` → `PERSON_ID_OPTIONAL`
- BatchView handler：8 行循环 → 1 行工厂调用
- UpdateTags/UpdateNote handler：5 行 → 1 行
- 提取 3 个独立 schema const（`_daliurenBatchViewSchema`、`_daliurenUpdateTagsSchema`、`_daliurenUpdateNoteSchema`）避免循环引用

**liuyaoFunctions.ts**：同大六壬，6 处 personId + BatchView + UpdateTags/UpdateNote

**wikiFunctions.ts**：

- 6 处 `personId` → `PERSON_ID_OPTIONAL`
- BatchView handler → 工厂调用
- ReplaceContent/InsertContent handler → 工厂调用
- 提取 3 个独立 schema const

**ziweiFunctions.ts**：

- 2 处 `personId` → `PERSON_ID_OPTIONAL`
- SetHoroscopeTime handler → 工厂调用
- 提取 `_setHoroscopeTimeSchema`

**personFunctions.ts**：

- 移除未使用的 `extractConfirmed` 导入

### 2.3 循环引用问题与解决

**问题**：handler 工厂在模块初始化时就访问 `functionName.zodSchema`，但此时函数对象尚未完成赋值，触发 `ReferenceError: Cannot access 'X' before initialization`。

**解决**：将 zodSchema 提取为独立的 `const _xxxSchema = z.object({...})`，函数定义中引用该 const，工厂也引用同一 const。这样 schema 在工厂调用时已经初始化完成。
