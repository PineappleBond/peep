## 2. 修复的 TS 类型错误

### 问题描述

第三轮修复了 47 个 TS 类型错误后，仍残留 4 个错误，均在 `updateRecordMetadata` 泛型调用处：

```
error TS2344: Type 'LiurenRecord' does not satisfy the constraint '{ id: number; }'.
  Types of property 'id' are incompatible.
    Type 'number | undefined' is not assignable to type 'number'.
```

### 根因分析

`updateRecordMetadata<T extends { id: number }>` 的泛型约束过严：

- `LiurenRecord` 和 `LiuyaoRecord` 的 `id` 字段是 `id?: number`（Dexie 自增主键，新建记录时可能没有 id）
- `getRecord` 函数的返回类型是 `T | undefined`（Dexie `.get()` 的行为），但参数签名要求 `T | null`
- `saveRecord` 函数的返回类型是 `Promise<number>`（Dexie `.put()` 返回 id），但参数签名要求 `Promise<void>`

### 修复方案

修改 `src/core/debugApi/helpers.ts` 中 `updateRecordMetadata` 的泛型约束和参数签名：

| 参数              | 修改前                     | 修改后                            |
| ----------------- | -------------------------- | --------------------------------- |
| 泛型约束          | `T extends { id: number }` | `T extends { id?: number }`       |
| getRecord 返回值  | `Promise<T \| null>`       | `Promise<T \| null \| undefined>` |
| saveRecord 返回值 | `Promise<void>`            | `Promise<unknown>`                |

## 3. 重构：提取 `withErrorHandling` 辅助函数

### 问题分析

debugApi 中每个函数都有相同的错误处理模式：

```typescript
export async function Foo(params) {
  const stop = timer("Foo");
  try {
    // ... 业务逻辑
    stop();
    return result;
  } catch (err) {
    if (err instanceof FooError) {
      stop();
      throw err;
    }
    log("error", "Foo", "执行失败", err);
    stop();
    throw wrapError("Foo", err, FooError);
  }
}
```

此模式在 person.ts、daliuren.ts、liuyao.ts、wiki.ts 中共出现 **20+ 次**，每次约 10 行样板代码。

### 解决方案

在 `helpers.ts` 中新增 `withErrorHandling` 函数：

```typescript
export async function withErrorHandling<T, E extends BaseDebugError>(
  label: string,
  ErrorClass: new (message: string, source: string, options?: any) => E,
  fn: () => T | Promise<T>,
): Promise<T> {
  const stop = timer(label);
  try {
    const result = await fn();
    stop();
    return result;
  } catch (err) {
    stop();
    if (err instanceof ErrorClass) throw err;
    throw wrapError(label, err, ErrorClass);
  }
}
```

### 应用范围

已将以下函数重构为使用 `withErrorHandling`：

| 文件          | 函数                                                                              | 代码减少      |
| ------------- | --------------------------------------------------------------------------------- | ------------- |
| `person.ts`   | PersonList, PersonGet, PersonCreate, PersonUpdate, PersonDelete, PersonSetDefault | 全部 6 个函数 |
| `daliuren.ts` | DaLiuRenUpdateTags, DaLiuRenUpdateNote                                            | 2 个函数      |
| `liuyao.ts`   | LiuYaoUpdateTags, LiuYaoUpdateNote                                                | 2 个函数      |
| `wiki.ts`     | WikiReplaceContent, WikiInsertContent                                             | 2 个函数      |

**总计**：12 个函数重构，消除约 **120 行**重复代码。

### 重构前后对比（以 PersonList 为例）

**重构前**（11 行）：

```typescript
export async function PersonList(): Promise<Person[]> {
  const stop = timer("PersonList");
  try {
    log("info", "PersonList", "查询人物列表");
    const persons = await listPersons();
    log("info", "PersonList", "查询成功", { count: persons.length });
    stop();
    return persons;
  } catch (err) {
    log("error", "PersonList", "查询失败", err);
    throw wrapError("PersonList", err, ZiWeiError);
  }
}
```

**重构后**（7 行）：

```typescript
export async function PersonList(): Promise<Person[]> {
  return withErrorHandling("PersonList", ZiWeiError, async () => {
    log("info", "PersonList", "查询人物列表");
    const persons = await listPersons();
    log("info", "PersonList", "查询成功", { count: persons.length });
    return persons;
  });
}
```

## 7. 后续优化建议

1. **继续推广 `withErrorHandling`**：daliuren.ts 和 liuyao.ts 中还有大量函数（computeDaLiuRenData、DaLiuRen、DaLiuRenCreate 等）仍使用旧模式，可逐步迁移
2. **lunar.ts 也用 `withErrorHandling` 重构**：当前 lunar.ts 仍使用手动 try/catch，但 lunar 函数是同步的，`withErrorHandling` 返回 Promise，需要权衡是否值得
3. **提取 personFunctions.ts 中的重复 Person schema**：`personListFunction` 和 `personGetFunction` 的 returns zodSchema 几乎完全相同，可提取 `_personBaseSchema` 共享
4. **补充 E2E 测试**：当前测试都是单元测试（mock DB），可考虑添加基于真实 IndexedDB 的集成测试
5. **WikiDelete 的 Function 注册**：debugApi 已有 WikiDelete 实现，但 rtcAgent 的 wikiFunctions.ts 未注册此 Function（需求文档中标注为"可选"），可根据实际需要决定是否开放
