## 一、审查发现

### 1.1 Handler 自引用模式（9 处）

六个 rtcAgent Function 文件中有 9 个 handler 使用 `xxxFunction.zodSchema.parse(args)` 自引用模式：

- `personFunctions.ts`：personGetFunction、personSetDefaultFunction
- `daliurenFunctions.ts`：daliurenViewFunction、daliurenListFunction
- `liuyaoFunctions.ts`：liuyaoViewFunction、liuyaoListFunction
- `wikiFunctions.ts`：wikiViewFunction、wikiListFunction
- `ziweiFunctions.ts`：ziweiFunction、getScopeDataFunction

**问题**：

- 自引用在 TypeScript 中可能触发 TS7022 推断循环错误（第九轮已修复部分）
- 与已建立的工厂函数模式（createPassthroughHandler）不一致
- 代码可读性差，handler 无法独立理解

### 1.2 重复 Schema 创建（2 处）

`daliurenListFunction` 和 `liuyaoListFunction` 在 zodSchema 和 handler 中分别调用 `createListFiltersSchema()`，导致每次模块加载时创建两个相同的 schema 对象。

### 1.3 helpers.ts 重复代码

- `waitForRecordSaved` 与 `waitForDocSaved` 逻辑完全相同（null 检查 + capped setTimeout + log），仅日志标签不同
- `isDialogOpen` 使用 if/else 链，新增页面类型需改动函数体

### 1.4 rtcAgent Function 模块缺少单元测试

除 `shared.test.ts` 外，6 个 Function 文件无任何测试。虽然 integration.test.ts 和 rtcAgent.test.ts 间接覆盖部分行为，但缺少结构一致性验证。

## 二、修复措施

### 2.1 消除 9 处 Handler 自引用

**方法**：提取 schema 到模块级变量 + 使用 `createPassthroughHandler` 工厂函数。

| 文件                 | Function                 | 提取的 Schema                | 工厂函数                 |
| -------------------- | ------------------------ | ---------------------------- | ------------------------ |
| personFunctions.ts   | personGetFunction        | `_personGetSchema`           | createPassthroughHandler |
| personFunctions.ts   | personSetDefaultFunction | `_personSetDefaultSchema`    | createPassthroughHandler |
| daliurenFunctions.ts | daliurenListFunction     | `_daliurenListFiltersSchema` | createPassthroughHandler |
| daliurenFunctions.ts | daliurenViewFunction     | `_daliurenViewSchema`        | createPassthroughHandler |
| liuyaoFunctions.ts   | liuyaoListFunction       | `_liuyaoListFiltersSchema`   | createPassthroughHandler |
| liuyaoFunctions.ts   | liuyaoViewFunction       | `_liuyaoViewSchema`          | createPassthroughHandler |
| wikiFunctions.ts     | wikiListFunction         | `_wikiListFiltersSchema`     | createPassthroughHandler |
| wikiFunctions.ts     | wikiViewFunction         | `_wikiViewSchema`            | createPassthroughHandler |
| ziweiFunctions.ts    | ziweiFunction            | `_ziweiSchema`               | createPassthroughHandler |
| ziweiFunctions.ts    | getScopeDataFunction     | `_getScopeDataSchema`        | createPassthroughHandler |

**重构前后对比**：

```ts
// 重构前（自引用 + 内联 schema）
export const personGetFunction = {
  zodSchema: z.object({ personId: PERSON_ID_OPTIONAL }),
  handler: (args: Record<string, unknown>) => {
    const input = personGetFunction.zodSchema.parse(args); // 自引用
    return peepApi().PersonGet(input.personId);
  },
};

// 重构后（模块级 schema + 工厂函数）
const _personGetSchema = z.object({ personId: PERSON_ID_OPTIONAL });

export const personGetFunction = {
  zodSchema: _personGetSchema,
  handler: createPassthroughHandler(_personGetSchema, (p: { personId?: number }) =>
    peepApi().PersonGet(p.personId),
  ),
};
```

### 2.2 helpers.ts 重构

**waitForPersist 提取**：

```ts
// 重构前：两个几乎相同的函数
export async function waitForRecordSaved(recordId, timeout) { ... }
export async function waitForDocSaved(docId, timeout) { ... }

// 重构后：共享私有辅助函数
async function waitForPersist(id, label, timeout) { ... }
export function waitForRecordSaved(id, timeout) { return waitForPersist(id, "记录", timeout); }
export function waitForDocSaved(id, timeout) { return waitForPersist(id, "文档", timeout); }
```

**isDialogOpen 查找表化**：

```ts
// 重构前：if/else 链
export function isDialogOpen(type) {
  if (type === "daliuren") return !!getOpenCreateDialog();
  if (type === "liuyao") return !!getOpenLiuyaoCreateDialog();
  return !!getOpenWikiEditor();
}

// 重构后：查找表，新增类型仅需扩展 map
const _dialogGetters = {
  daliuren: () => getOpenCreateDialog(),
  liuyao: () => getOpenLiuyaoCreateDialog(),
  wiki: () => getOpenWikiEditor(),
};
export function isDialogOpen(type) {
  return !!_dialogGetters[type]();
}
```

## 四、本轮优化亮点

1. **工厂模式全覆盖**：所有只读 handler 统一使用 `createPassthroughHandler`，消除最后一批自引用模式
2. **结构一致性测试**：260 个测试用例覆盖全部 39 个 Function 的 6 个结构属性，确保未来新增 Function 遵循相同规范
3. **查找表替代条件链**：`isDialogOpen` 从 if/else 链改为查找表，符合开闭原则
4. **共享辅助函数**：`waitForPersist` 提取消除重复逻辑，保留语义清晰的公开 API（waitForRecordSaved/waitForDocSaved）
