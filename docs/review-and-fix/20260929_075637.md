# 第八轮代码审查与修复报告

**时间**：2026-09-29 07:56
**审查范围**：`src/core/rtcAgent/` 模块 + 代码审查 agent 反馈
**聚焦方向**：重复代码消除、Bug 修复、死代码清理、类型安全提升

## 1. 问题发现

通过全面代码审查（含自动化 agent 分析），发现以下问题：

### 1.1 重复代码：`createMetadataUpdateHandler` 与 `createPassthroughHandler` 完全相同

`shared.ts` 中两个工厂函数的签名、实现、返回值完全一致——都是 `parse → call` 模式。`createMetadataUpdateHandler` 纯粹是 `createPassthroughHandler` 的重复。

### 1.2 lunarFunctions.ts 未使用已有工厂函数

9 个 Lunar Function 全部手写相同的 `parse→call` 样板代码，而 `createPassthroughHandler` 工厂已经定义好却从未在生产代码中使用。

### 1.3 Bug：`SetHoroscopeTime` 返回值 `hour` 描述错误

输入 schema 定义 `hour` 为 `z.number().int().min(0).max(23)`（24 小时制），但返回 schema 描述为"时辰索引 0-11"。两个语义互相矛盾，属于复制粘贴 Bug。

### 1.4 死代码：`PERSON_ID_REQUIRED` 从未使用

`shared.ts` 中定义并导出了 `PERSON_ID_REQUIRED`，但整个代码库中无任何消费者。

### 1.5 类型安全：`biFa` 字段使用 `z.any()`

`daliurenFunctions.ts` 中 `biFa: z.array(z.any())` 完全跳过 Zod 校验，任意值都能通过。实际上 `BiFaMatch` 接口有清晰的结构定义。

### 1.6 不必要导出：6 个 schema 常量从未被外部导入

`daliurenResultSchema`、`daliurenRecordSchema`、`liuyaoChartSchema`、`liuyaoYongSchema`、`liuyaoRecordSchema`、`hbarSchema` 都加了 `export` 但无外部消费者。

### 1.7 一致性问题：`personFunctions.ts` 未使用共享 schema

`personGetFunction` 内联定义了 `personId` 字段，未使用共享的 `PERSON_ID_OPTIONAL`。

### 1.8 Bug：`personUpdateFunction` 泄露 `confirmed` 字段

`personCreateFunction` 通过 `mergeBirthInput` 间接过滤了 `confirmed`，但 `personUpdateFunction` 直接将含 `confirmed: true` 的完整 input 传给 API，与其他模块使用 `extractConfirmed` 的做法不一致。

---

## 2. 修复方案

### 2.1 消除重复：`createMetadataUpdateHandler` 改为别名

```ts
export const createMetadataUpdateHandler = createPassthroughHandler;
```

保留名称仅为语义清晰（调用点一看便知是「更新元数据」而非「透传」），实现不再重复。

### 2.2 lunarFunctions.ts 全面重构

- 9 个 handler 全部改用 `createPassthroughHandler` 工厂
- 提取共享 schema：`_dateRequired`、`_dateOptional`、`_ganZhiPair`、`_solarTermItem`、`_solarTermNullable`
- 文件从 354 行减至 229 行（减少 125 行），可读性提升

### 2.3 Bug 修复

| Bug                                   | 修复                                         |
| ------------------------------------- | -------------------------------------------- |
| `SetHoroscopeTime` 返回 hour 描述错误 | `"时辰索引 0-11"` → `"设置的小时（0-23）"`   |
| `personUpdateFunction` 泄露 confirmed | 添加 `extractConfirmed` 调用，与其他模块一致 |

### 2.4 死代码清理

- 移除 `PERSON_ID_REQUIRED`（零消费者）
- 6 个 schema 常量移除 `export` 关键字（保留定义，仅限制作用域）

### 2.5 类型安全提升

`biFa` 从 `z.array(z.any())` 改为精确 schema：

```ts
biFa: z.array(
  z.object({
    rule: z.object({
      code: z.string(),
      name: z.string(),
      description: z.string(),
    }),
    evidence: z.array(z.string()),
  }),
);
```

### 2.6 一致性修复

`personGetFunction` 的 `personId` 改用 `PERSON_ID_OPTIONAL`，与其他模块保持一致。
