## 二、详细变更说明

### 2.1 updateRecordMetadata 参数收敛（ESLint max-params 修复）

**问题**：函数有 7 个位置参数，违反 `max-params`（上限 5）规则，且调用方可读性差（多个 `undefined` 占位）。

**解决方案**：改为 `recordId + options` 对象模式：

```typescript
// Before（调用方）
await updateRecordMetadata<LiurenRecord>(
  params.recordId,
  getLiurenRecord,
  saveLiurenRecord,
  record => ({ ...record, tags: params.tags }),
  invalidateLiurenTagCache,
  DaLiuRenError,
  "DaLiuRenUpdateTags",
);

// After
await updateRecordMetadata<LiurenRecord>(params.recordId, {
  getRecord: getLiurenRecord,
  saveRecord: saveLiurenRecord,
  updateFn: record => ({ ...record, tags: params.tags }),
  invalidateCache: invalidateLiurenTagCache,
  ErrorClass: DaLiuRenError,
  source: "DaLiuRenUpdateTags",
});
```

**涉及文件**：`helpers.ts`（定义）、`daliuren.ts`（2 处调用）、`liuyao.ts`（2 处调用）、`helpers.metadata.test.ts`（12 处测试调用）。

### 2.2 ListQueryParams 共享类型

**问题**：`DaLiuRenListParams`、`LiuyaoListParams`、`WikiListParams` 结构完全相同（personId、searchText、tags、page、pageSize），但各自重复定义。

**解决方案**：

```typescript
export interface ListQueryParams {
  personId?: number;
  searchText?: string;
  tags?: string[];
  page?: number;
  pageSize?: number;
}

export type DaLiuRenListParams = ListQueryParams;
export type LiuyaoListParams = ListQueryParams;
export type WikiListParams = ListQueryParams;
```

使用 `type` 别名而非空 `interface extends`，避免 ESLint `@typescript-eslint/no-empty-object-type` 警告。同时在 `index.ts` 导出 `ListQueryParams` 供外部使用。

### 2.3 Schema 工厂函数

**问题**：`daliurenFunctions.ts` 和 `liuyaoFunctions.ts` 中 UpdateTags/UpdateNote 的 Zod schema 定义几乎完全重复，仅描述文字不同。

**解决方案**：在 `rtcAgent/shared.ts` 新增两个工厂函数：

```typescript
export function createUpdateTagsSchema(recordField: string, recordLabel: string) { ... }
export function createUpdateNoteSchema(recordField: string, recordLabel: string) { ... }
```

各业务模块只需传入字段名和标签即可生成 schema。由于 TypeScript 无法推断 `[recordField]` 计算属性名的字面量类型，调用处使用 `as unknown as { parse: ... }` 类型断言。

### 2.4 循环依赖消除

**问题**：`nextFrame` 最初定义在 `helpers.ts`，但 `callbacks.ts` 也需要使用。如果 `callbacks.ts` 从 `helpers.ts` 导入，会形成 `helpers → callbacks → helpers` 循环依赖。

**解决方案**：将 `nextFrame` 移至 `logger.ts`（模块图中的叶依赖），`helpers.ts` 通过 `export { nextFrame }` 重新导出保持向后兼容。

### 2.5 waitForStableValue 提取

**问题**：`waitForStateUpdate` 和 `waitForAstrolabeStable` 都包含相同的「连续 N 次采样相同值才认为稳定」模式。

**解决方案**：提取私有辅助函数 `waitForStableValue`，两者复用：

```typescript
async function waitForStableValue(
  getValue: () => string | null,
  timeout: number,
  requiredStable = 3,
  label = "值稳定",
): Promise<boolean>;
```

### 2.6 其他小优化

- **`callbacks.ts`**：`setTimeout(50)` → `nextFrame()`，与 React 渲染周期对齐，减少不必要的延时
- **`callbacks.ts`**：`_pageErrorClass` 查找表替代 if/else 链，新增页面类型只需扩展 Record
- **`person.ts`**：清理 `PersonSetDefault` 解构中的 void 模式
- **`lunarFunctions.ts`**：内联 schema 提取为 `_lunarToSolarSchema` 具名变量，保持一致性
