## 二、发现的问题与优化

### 2.1 重复的 `ErrorClass` 类型签名（7 处 eslint-disable）

**问题**：`validate.ts`、`helpers.ts`、`errors.ts` 中共 7 处使用以下模式：

```ts
// eslint-disable-next-line @typescript-eslint/no-explicit-any
ErrorClass: new (message: string, src: string, options?: any) => Error
```

每次出现都需要一条 `eslint-disable` 注释绕过 `no-explicit-any` 规则。这是 **同义类型的重复定义**，违反 DRY 原则。

**修复**：在 `errors.ts` 中定义统一泛型类型 `ErrorConstructor<E>`：

```ts
export type ErrorConstructor<E extends BaseDebugError = BaseDebugError> = new (
  message: string,
  source: string,
  options?: {
    context?: Record<string, unknown>;
    suggestion?: string;
    cause?: unknown;
    errorCode?: ApiErrorCodeType;
  },
) => E;
```

然后所有 7 处替换为 `ErrorConstructor` 或 `ErrorConstructor<E>`，**消除全部 7 条 eslint-disable 注释**。

**影响文件**：`errors.ts`、`validate.ts`（5 处）、`helpers.ts`（2 处）、`index.ts`（类型导出）

---

### 2.2 重复的确认机制样板代码（10 处）

**问题**：每个写操作 handler（Create/Update/Delete）都重复以下结构：

```ts
if (!parsedArgs.confirmed) {
  return {
    _needsConfirmation: true,
    action: "动作名",
    summary: "摘要内容",
    message: "请向用户确认...",
  };
}
const { confirmed: _c, ...params } = parsedArgs;
void _c;
```

此模式在 `personFunctions.ts`（3 处）、`daliurenFunctions.ts`（2 处）、`liuyaoFunctions.ts`（2 处）、`wikiFunctions.ts`（2 处）共出现 **9 次**，每次仅 action/summary/message 不同。

**修复**：提取两个辅助函数到 `shared.ts`：

- `needsConfirm(action, summary, message?)` —— 构建标准确认响应
- `extractConfirmed(args)` —— 去除 confirmed 字段，返回纯业务参数

重构后每个 handler 从 ~12 行缩减到 ~5 行：

```ts
if (!parsedArgs.confirmed) {
  return needsConfirm("创建人物", `即将创建人物：${parsedArgs.name}`);
}
const params = extractConfirmed(parsedArgs);
```

**影响文件**：`shared.ts`、`personFunctions.ts`、`daliurenFunctions.ts`、`liuyaoFunctions.ts`、`wikiFunctions.ts`、`rtcAgent.ts`

### 2.3 纯计算函数缺少同步版错误处理包装器

**问题**：`computeDaLiuRenData` 是同步的纯计算函数，使用手动 `try/catch + timer + wrapError` 样板。`withErrorHandling` 是异步的（返回 `Promise<T>`），无法直接用于同步函数——强行使用会改变函数签名，导致下游调用方报错。

**修复**：新增 `withErrorHandlingSync<T, E>()` —— 同步版的错误处理包装器：

```ts
export function withErrorHandlingSync<T, E extends BaseDebugError>(
  label: string,
  ErrorClass: ErrorConstructor<E>,
  fn: () => T,
): T {
  const stop = timer(label);
  try {
    const result = fn();
    stop();
    return result;
  } catch (err) {
    stop();
    if (err instanceof ErrorClass) throw err;
    throw wrapError(label, err, ErrorClass);
  }
}
```

`computeDaLiuRenData` 重构为使用 `withErrorHandlingSync`，从 17 行缩减到 8 行，保持同步签名。

**影响文件**：`helpers.ts`、`daliuren.ts`、`index.ts`
