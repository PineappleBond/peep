## 二、Bug 修复

### 2.1 rtcAgent.test.ts / integration.test.ts：`z.void is not a function`

**症状**：两个测试文件在加载 `rtcAgent.ts` 时崩溃，报 `TypeError: z.void is not a function`。

**根因**：`@rtc-agent/component` 的 mock 对象只模拟了 `object/string/number/enum/boolean/array` 6 个 Zod 工厂函数，但 `rtcAgent.ts` 实际使用了 `z.void()`、`z.record()`、`z.any()`、`.extend()`、`.nullable()` 等 API。

**修复**：在两个测试文件的 mock 中补齐缺失的 Zod 工厂方法和链式方法。

**文件**：

- `src/core/integration.test.ts`
- `src/core/rtcAgent.test.ts`

### 2.2 liuyao.ui.test.ts：`selectPerson` 未被调用

**症状**：`LiuYaoView UI 模式 > 完整 UI 流程` 测试失败，断言 `selectPerson` 被调用但实际调用次数为 0。

**根因**：`helpers.ts` 中的 `uiState` 是模块级单例，跨测试泄漏。前序测试设置了 `currentPersonId = 1` 后，后续测试中 `selectPersonAndWait(1)` 因 `uiState.currentPersonId === 1` 直接跳过选择。

**修复**：

1. `helpers.ts` 新增 `resetUiState()` 导出函数，将所有 UI 状态追踪字段重置为初始值。
2. `liuyao.ui.test.ts` 的 `beforeEach/afterEach` 中调用 `resetUiState()`。

**文件**：

- `src/core/debugApi/helpers.ts`
- `src/core/debugApi/liuyao.ui.test.ts`
- `src/core/debugApi/index.ts`（导出 `resetUiState`）

### 2.3 liuyao.ui.test.ts：`result.computed` 可能为 `undefined`

**症状**：TypeScript 编译报错 `TS18048: 'result.computed' is possibly 'undefined'`。

**根因**：`LiuyaoViewResult` 类型中 `computed` 是可选字段（`computed?: LiuyaoComputedData`），测试中在 `expect(result.computed).toBeDefined()` 之后直接访问属性，TypeScript 无法推断已验证。

**修复**：在 `toBeDefined()` 之后的属性访问使用非空断言 `result.computed!.xxx`。

## 三、新增 Function

### 3.1 人物库

| Function           | 签名                                    | 说明                             |
| ------------------ | --------------------------------------- | -------------------------------- |
| `PersonSetDefault` | `(personId: number) => Promise<Person>` | 设置默认人物，自动取消原默认标记 |

**设计要点**：

- 复用 `savePerson(id, input, true)` 的事务机制，自动清除其他人默认标记
- 提取 Person 对象的 BirthInput 字段后传入 `savePerson`
- 触发 `globalEvents.emit("person.changed")` UI 同步

### 3.2 大六壬

| Function             | 签名                                                                | 说明             |
| -------------------- | ------------------------------------------------------------------- | ---------------- |
| `DaLiuRenUpdateTags` | `(params: {recordId, tags}) => Promise<LiurenRecord>`               | 更新起课记录标签 |
| `DaLiuRenUpdateNote` | `(params: {recordId, note?, background?}) => Promise<LiurenRecord>` | 更新备注/背景    |

**设计要点**：

- 仅更新元数据，不修改卦象数据（符合业务约束"记录不可修改"）
- 更新后自动调用 `invalidateLiurenTagCache()` 使标签缓存失效
- 支持部分更新（note 和 background 可单独传）

### 3.3 六爻

| Function           | 签名                                                                | 说明             |
| ------------------ | ------------------------------------------------------------------- | ---------------- |
| `LiuYaoUpdateTags` | `(params: {recordId, tags}) => Promise<LiuyaoRecord>`               | 更新起卦记录标签 |
| `LiuYaoUpdateNote` | `(params: {recordId, note?, background?}) => Promise<LiuyaoRecord>` | 更新备注/背景    |

**设计要点**：与大六壬对称设计，同样支持部分更新和缓存失效。

### 3.4 Wiki

| Function             | 签名                                                                             | 说明                     |
| -------------------- | -------------------------------------------------------------------------------- | ------------------------ |
| `WikiReplaceContent` | `(params: {docId, searchText, replaceText, isGlobal?}) => Promise<WikiDocument>` | 内容字符串替换           |
| `WikiInsertContent`  | `(params: {docId, content, position?}) => Promise<WikiDocument>`                 | 按行号/开头/结尾插入内容 |

**设计要点**：

- `WikiReplaceContent`：`isGlobal` 默认 `true`（全局替换）。使用 `split().join()` 而非 `replaceAll()` 以兼容 ES2020 目标库。
- `WikiInsertContent`：`position` 支持三种模式——正整数（1-based 行号）、`"start"`（文档开头）、`"end"`（文档结尾，默认）。行号超出范围时自动插入末尾。
- 两者都自动更新 `updatedAt` 时间戳。

### 3.5 紫微斗数

| Function           | 签名                                                                                  | 说明         |
| ------------------ | ------------------------------------------------------------------------------------- | ------------ |
| `SetHoroscopeTime` | `(params: {personId?, year, month, day, hour?}) => Promise<{year, month, day, hour}>` | 设置运限时间 |

**设计要点**：

- 封装 `setHoroscopeTimeWithRetry`，对外暴露为纯参数 API
- 自动从 `getGetZwds()` 获取 Zwds 状态
- 包含完整的错误处理：Zwds 不可用、日期无效、重试失败
