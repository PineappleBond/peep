# 运势分析工作流

用户想查看某个时间段的运势，如"看看我这个月的运势"、"分析一下今年的整体运势"。

## 流程总览

1. **阶段一：信息收集** — 确定人物、读取回忆录、明确用户关切
2. **阶段二：排盘** — 八字排盘 + 紫微排盘 + 可选六爻起卦
3. **阶段三：专家分析** — 派发病字/紫微/六爻专家子代理，各自独立分析
4. **阶段四：整合报告** — 汇总共识、解释差异、给出建议

## 阶段一：信息收集

**目标**：确定分析主体、了解背景、明确用户关切。

1. `script` 获取人物列表
   - 空 → `ask_user` 引导创建人物
   - 多个 → `ask_user` 选择分析对象
   - 一个 → 直接使用该人物

2. `script` 读取该人物的回忆录
   - 了解用户的过往经历、重大事件、情绪状态
   - 提取与分析时段相关的关键信息，整理为结构化摘要

3. 确定分析时间范围（本月/本季度/今年/自定义）

4. `ask_user` 补充信息（可根据回忆录已有内容省略）：
   - 你主要关心哪些方面？（财运 / 感情 / 事业 / 健康 / 综合）
   - 近期有没有特别关注的事件或决策？

> **⚠️ 不要跳过回忆录。** 不了解用户背景就开始排盘分析，等于盲人摸象。

## 阶段二：排盘

**目标**：获取命理数据。

1. `script` 八字排盘
2. `script` 紫微排盘
3. 询问用户是否需要起六爻卦（可选，用于更精准的特定问题预测）
   - 用户同意 → `script` 起卦并保存
   - 用户不同意 → 跳过，进入阶段三

> 六爻不是必须的，用户不同意就跳过，不要反复劝说。

## 阶段三：专家协同分析

### 前置步骤（主 Agent 执行）

从阶段一收集的回忆录中，提取与分析时段相关的关键信息，整理为结构化摘要：

- **重大事件**：过往发生的重要事情（时间 + 事件 + 影响）
- **情绪状态**：用户近期的心理状态和关注点
- **已知趋势**：从过往经历中可以看到的模式

此摘要将作为上下文嵌入各专家子代理的 prompt，**避免每个专家重复读取回忆录**。

### 派发专家子代理

使用 `sub_agent` 工具派发专家，每个专家的 prompt 必须包含以下信息：

#### 八字专家 prompt

```text
你是八字命理专家。请基于以下信息进行分析：

**命主背景**：
{回忆录摘要}

**排盘数据**：
{八字排盘结果}

**分析时段**：{时间范围}

**用户关切**：{关心的领域}

**分析要求**：
1. 先独立推导运势趋势，不要预设结论
2. 对用户关切的领域重点分析
3. 不确定的地方明确标注"此象不确定"
4. 用词克制：用"可能""倾向"，禁用"一定""必然"
5. 禁止事后套用：不要因为已知结果就反过来找证据
6. 给出 1-3 条具体可操作的建议
```

#### 紫微专家 prompt

```text
你是紫微斗数专家。请基于以下信息进行分析：

**命主背景**：
{回忆录摘要}

**排盘数据**：
{紫微排盘结果}

**分析时段**：{时间范围}

**用户关切**：{关心的领域}

**分析要求**：
1. 先独立推导运势趋势，不要预设结论
2. 对用户关切的领域重点分析
3. 不确定的地方明确标注"此象不确定"
4. 用词克制：用"可能""倾向"，禁用"一定""必然"
5. 禁止事后套用：不要因为已知结果就反过来找证据
6. 给出 1-3 条具体可操作的建议
```

#### 六爻专家 prompt（仅当起卦后派发）

```text
你是六爻占卜专家。请基于以下信息解卦：

**命主背景**：
{回忆录摘要}

**卦象数据**：
{六爻卦象结果}

**用户问题**：{具体问题}

**分析要求**：
1. 先独立解读卦象，不要预设结论
2. 不确定的地方明确标注"此象不确定"
3. 用词克制：用"可能""倾向"，禁用"一定""必然"
4. 禁止事后套用：不要因为已知结果就反过来找证据
5. 给出具体可操作的建议
```

> **回忆录过大？** 如果回忆录超过 2000 字，先 `sub_agent` 派发一个整理子代理提取关键信息，再将摘要传给各专家。

## 阶段四：整合报告

**目标**：汇总各专家结论，生成综合报告。

### 整合策略

1. **共识优先**：多个领域一致的结论放在最前面，这是最有信心的判断
2. **差异解释**：矛盾的结论要说明原因（不同体系的视角差异，如八字看大趋势、紫微看具体宫位）
3. **不确定性标注**：明确告知用户哪些方面分析结果不确定，不要硬凑统一结论
4. **行动建议**：基于分析给出具体可操作的建议，按优先级排序

### 收尾操作

1. 询问用户是否保存报告 → `script` 保存（可打标签：运势分析、八字、紫微）
2. `script` 打开八字页面，让用户查看详细排盘
3. `script` 打开紫微页面
4. 询问是否需要针对某个方面深入分析

## 注意事项

1. **所有业务操作**：通过 `script` 工具执行 TypeScript 代码，具体函数参考 `/functions/INDEX.md`
2. **回忆录先行**：阶段一就必须读取回忆录，不要推迟到专家分析阶段
3. **用户关切导向**：分析要围绕用户关心的领域展开，不要面面俱到但都不深入
4. **六爻不强求**：用户不同意起卦就跳过，不要反复劝说
5. **专家独立性**：各专家子代理必须独立分析，不要在 dispatch 前就把结论透给他们
6. **承认不确定**：命理能看趋势，不能断言具体事件；不确定的地方要诚实标注
