# 场景文件编写指南

## 核心理念：缰绳，不是轨道

场景文件是**缰绳**，用于控制 Agent 的方向；不是**轨道**，不规定 Agent 的具体路径。

- **缰绳**：告诉 Agent 方向和原则，具体怎么走它自己判断
- **轨道**：规定死板的步骤，Agent 只会照搬

我们要做的是 harness agent——指引它，而不是要求它怎么做。

## 场景文件的职责

### 应该包含

- **目标**：一句话定位这个场景解决什么问题
- **场景特有逻辑**：
  - 何时触发（判断条件、信号）
  - 需要注意的事项
  - 关键的决策点
  - 与 PERSONA 或其他场景的边界

### 不应该包含

- ❌ **示例对话**：具体的对话内容容易误导 Agent 照搬格式和表达
- ❌ **Function 列表**：Function 文档已自动生成，场景文件不应重复
- ❌ **具体的解读内容**：如盘面分析的具体措辞、术语解释的格式
- ❌ **死板的流程步骤**：如"先做 A，再做 B，最后做 C"
- ❌ **与 PERSONA 重复的内容**：角色设定、表达风格、通用工作节奏

## 文件格式

```markdown
---
title: 场景名称
tags: [tag1, tag2, tag3]
description: 一句话描述
---

# 场景名称

## 目标

一句话定位这个场景解决什么问题。

## 场景特有逻辑

### 判断条件 / 触发信号

描述何时应该进入这个场景。

### 注意事项

描述这个场景特有的约束、边界、注意点。

### 决策点

描述 Agent 需要做出判断的关键时刻。
```

## 设计原则

### 1. 只写"做什么"和"为什么"，不写"怎么做"

**反例**：

```markdown
1. 先调用 WikiList 查询历史记录
2. 再调用 ZiWei 获取盘面数据
3. 对比两者，得出结论
```

**正例**：

```markdown
用现实信息验证假设——whatever 形式，历史印证、用户反馈、已有记录，或者其他你能想到的方式——目的是找到区分假设的依据。
```

### 2. 给 Agent 留空间

不要规定：

- 假设的数量（"建立 3-5 个假设"）
- 具体的对比维度
- 输出的格式模板

### 3. 避免举例误导

举例很难，因为例子最容易误导 Agent。

- 如果必须举例，用抽象的占位符
- 不要写具体的对话内容
- 不要写具体的解读措辞

### 4. 边界清晰

- 明确这个场景**何时使用**
- 明确这个场景**何时不使用**（应该走其他场景）
- 明确与其他场景的**协作关系**

## Function 文档

Function 文档由 `rtc-agent` 自动生成，包含：

- 参数说明
- 返回值说明
- 调用示例

场景文件**不应重复**这些内容。如果某个 Function 在这个场景中有特殊的使用注意事项，只需提及注意事项本身，不需要介绍 Function 是什么。

## 检查清单

新增场景文件前，对照检查：

- [ ] 是否只包含场景特有逻辑？
- [ ] 是否去掉了示例对话？
- [ ] 是否去掉了 Function 列表？
- [ ] 是否与 PERSONA 重复？
- [ ] 是否给了 Agent 充分的判断空间？
- [ ] 是否只写了方向和原则，没写具体路径？
